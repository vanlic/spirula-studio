# 基于全景相机共视的轴对齐场景分区

`axis-aligned` 分区方法面向 360° 全景采集的两个场景。一个是沿直路采集的狭长轨迹，另一个是沿单栋大楼四周采集的回字形闭环。两者都以近似同一高度的室外轨迹为前提。现有方法和数据流见[场景分区](scene-partition.md)。

流程为**整理全景站位 → 估计场景轴 → 共视预分区 → 拟合直角边界 → 选扩展站位 → 汇集种子点**。一个站位指一次全景采集。每站有唯一的核心区，可以整站借给其他区。每个三维位置有唯一的空间归属，供训练 ROI 和最终合并使用。每区的种子点列表可以有重叠。

## 使用

GUI 在分区面板的「切分方式」里选择「全景轴对齐」，默认根据站位分布判断是否沿直路切分。需要手动指定时，在「高级」中勾选「强制直路」。CLI 中自动判断对应 `--route loop`，强制直路对应 `--route road`。

计算完成后，可以在「预览阶段」切换「初始分组」和「拟合边界」。初始分组按共视图的分组标签给相机着色，点云使用原色，分组表可单独高亮一组。拟合边界按最终核心归属着色，显示空间边界，选中某区时用淡色显示外环。两阶段的编号各自独立，切换时保持视角。若计算为满足图像预算而重试，初始分组显示最终采用的那一轮。

```text
spirula partition split <dataset> --method axis-aligned --route road --max-images 400
spirula partition split <dataset> --method axis-aligned --route loop --parts 4
```

按图像上限切分时，核心和扩展图像合计受限。固定区数时，日志报告超出图像上限的分区。日志还记录场景轴置信度和各区借入站位前后的未覆盖点数。可用 `--outside-seed-fraction` 调整保留的区外种子点比例。

## 输入与计数

- 等距柱状全景图每帧对应一个站位。多视图全景按 COLMAP 的 `frames.bin`、`frames.txt` 或 Spirula SfM 的 `rigs.txt` 归并，后者也适用于保留原始双鱼眼的采集。Spirula 导出的 `cam0` 至 `cam5` 或 `cam9` 同编号透视面也可归并。双镜头的视图中心可以略有偏移，站位中心优先用 rig 原点，否则取该站相机中心的均值。导出形式见[数据集文档](../datasets.md#360-cameras-gopro-max-and-max-2-360)。
- 共视分组、切面归属和扩展选择都按站位进行。来自同一站的多个视图看到同一点时，在站位共视统计中计一次。`--max-images` 仍按交给训练的图像数计，站位的成本等于它对应的图像数。

## 1. 从相机中心估计场景轴

1. 从 `ParsedDataset::c2w` 和站位映射取中心，每个站位用一个中心参与估轴。
2. 定竖直轴。数据集有可靠的已定向标记时采用其 `+Z`，否则复用数据集解析的姿态定向逻辑。回字形轨迹近似共面时，可用站位分布的平面法向补充判断，并由姿态确定正负。直路站位近共线时，平面法向存在歧义，优先用全景姿态或数据集轴回退，并记录来源。
3. 定水平轴。直路对水平面上的所有站位中心做主成分分析，以最大方差方向为 `x`。两根主轴的方差差除以总方差就是方向置信度，整段拟合可减轻左右摆动对方向的影响。回字形在同一目录和文件名前缀内按帧号排序，同站的多视图共用一票。在轨迹上按场景跨度取三种距离的窗口，跳过跨大间隔的窗口，两半方向一致的窗口获得更高权重。设窗口首尾方位角为 `θ`，对 `cos(4θ)` 和 `sin(4θ)` 求加权均值 `C`、`S`，得到主轴角 `atan2(S, C) / 4` 及其垂直方向。相反和正交的位移给同一组轴投票，`(C, S)` 的长度给出置信度。缺少可排序的帧号或方向证据弱时，采用数据集轴在水平面上的投影。
4. 以相机中心的稳健中心 `o` 为原点，构造右手正交基 `R = [x, y, z]`，令 `q = Rᵀ(p − o)`。切分在 `q` 坐标中进行，保存区域时将切面表达在源数据集坐标中。相机外参、点云坐标和训练输出沿用现有坐标流程。

本步输出原点、三根轴、方向来源及置信度。场景轴用于约束候选切面的方向，切面的位置由第 3 步决定。预览在全景站位轨迹和区域边界上叠加场景轴，显示估计来源、水平置信度以及是否采用了回退方向。回字形还要检查两根水平轴是否分别贴合两组对边。

## 2. 按相机共视做初始分组

1. 复用现有 COLMAP 观测轨迹，按站位聚合出共视图，边权是两站共同观测到的去重点数。回字形重点保留相邻立面和楼角的真实共视，以及闭环首尾之间有观测支持的边。全景投影覆盖几乎所有方向，单凭投影容易把楼背面当成可见。首版缺少可靠轨迹时直接回退到基于站位距离的近邻图，并标记覆盖统计不可用。全景近邻图无需单一前视方向。
2. 复用 `viewgraph` 的 `graph::cut_labels` 在站位图上做归一化割。节点成本是站位对应的图像数。固定区数时以 `--parts` 为目标。按容量自动分区时使用核心图像预算，先给扩展站位留余量，再根据第 4 步的实际需求调整。
3. 保留初始组标签、图边权和每组图像数。弱连接和孤立站位沿用视图图分区的归并思路。初始标签作为拟合边界的依据，最终核心标签由第 3 步的空间切分给出。

## 3. 用共视分组拟合横平竖直的边界

两类场景共用递归正交切分和同一套切面评分。试验时显式指定直路或回字形，以便独立验证候选切面策略。首版只用竖直切面，每个叶区在俯视图上是矩形，外围区可沿部分轴向外延伸。切面沿竖直轴贯穿全高，地面、立面和屋顶都按同一平面归属。

1. 在当前区内沿场景允许的水平轴对站位中心排序，在相邻位置的间隙中生成候选切面。切面形如 `x = t` 或 `y = t`。根据初始分组、共视、容量和覆盖给候选排序。
2. 为每个候选评估四项代价。两侧都必须有相机。固定区数时给两侧分配叶区数，排除明显无法达到配额的候选。按预算时继续细分超限区。代价权重待用真实数据标定。
   - **共视代价**取被切断的边权占当前区内边权的比例。
   - **标签破碎度**可用 `Σ_g min(n_g_left, n_g_right) / n`，其中 `g` 为初始组，`n` 为当前区的站位数。
   - **容量代价**衡量两侧每个计划叶区要容纳的核心图像数是否均衡。
   - **区内点覆盖代价**用同一批确定性抽样的三维点评估当前区的所有候选。把点和站位中心按候选切面分别归到两侧。对每侧有观测记录的区内点，计算其中没有任何同侧核心站位观测的比例，再对有样本的两侧取平均。这样即使切断的共视边很少，也会对预计需要大量借站位的切面加代价。缺少点观测时跳过此项，并在诊断中标明覆盖率不可用。
3. 选代价最低且可行的切面继续递归。固定区数时，后续遇到无法细分的子区则回到候选切面重新尝试。若单站图像数已超过单区预算，或空间上无法切出指定区数，报出约束冲突。候选同分时按轴序和切面位置稳定决胜。
4. 用最终叶区确定核心站位，再将区号赋给站位所属的每张图，得到 `frame_label`。切面统一规定 `q[a] < t` 归低侧，`q[a] ≥ t` 归高侧，三维点和合并时的 splat 中心使用同一规则。任一切面移动都要重算受影响的站位归属。输出最终共视割边比例、每区核心图的连通分量数，以及初始组被拆开的程度。

### 直路

- 沿道路轴 `x` 排列站位，只用 `x = t` 横断道路。每区对应一段连续里程，道路、两侧人行道和沿街立面使用同一里程切口。
- 重点检查路边立面和路口附近的跨段覆盖。挑切面时，比较不同里程位置对两侧沿街几何的影响。扩展站位按实际点观测选取，相邻段和更远的路段都可以提供覆盖。

### 绕大楼的回字形

- 自动判断先在水平面检查站位分布。如果 PCA 短轴的方差至多为长轴的 1%（标准差比至多 10%），则按直路沿里程分段。此时采用 PCA 长轴，省略循环顺序评分，GUI 和日志会提示检测到直线轨迹。
- 允许 `x = t` 和 `y = t`，在四条边及转角附近共同比较候选。分区数由预算或 `--parts` 决定。一个区可以覆盖连续的转角和相邻边段。
- 在俯视图上按站位绕包围盒中心的极角构建循环顺序。评分优先保留连续的弧段，跨过循环起点的一段仍视为连续。这个顺序适用于单栋大楼四周的近似矩形单环，用站位共视和预览检查实际的相邻立面。
- 楼角可能同时被相邻两边看到。用区内点覆盖代价比较切在转角前、后或附近的效果，再从两侧观测中补扩展站位。尤其检查楼角、对侧立面和闭环首尾处的接缝。

## 4. 挑选扩展站位

先按边界计算每个三维点的空间归属 `point_label`，供可见性统计使用。然后只考察某区核心集合之外的站位，统计该站全部视图看到的去重区内点数和可见性权重占比。

### 常规外环

有观测数据时，参考 `graph` 方法，以点到站位中心的距离平方倒数加权，截断近点的最高权重，再按站位归一化。区内点权重占整站可见点权重的比例达到 `--ring`（默认 `0.1`），且命中区内点数达到 `--ring-min-points`（默认 `20`）时，该站位进入常规外环候选。只有站位近邻图时，以连到目标区核心站位的边权占比作判断。

固定区数模式保留常规达标候选，报告每区实际图像数及超额量。按 `--max-images` 自动分区时，预算计入**核心 + 扩展**。出现超额时先缩小核心预算并重新切分、统计和选环。达到重试上限后，在剩余图像名额内从达标候选中逐站挑选，每次纳入该站的全部已注册图像，并报告被预算裁掉的候选。

名额有限且有点观测时，以核心站位已经看到的区内点作为初始覆盖集合。每次在放得下的候选中，优先选每张新增图像能补齐最多未覆盖区内点的站位。纳入后更新覆盖集合，再计算下一轮的增益。每站图像数相同时，这等同于按新增点数排序。同分时按区内权重占比、命中点数和稳定站位索引决胜。只有近邻图时，按连到目标区的边权占比和稳定站位索引挑选。

### 用剩余名额补覆盖

一个站位即使看到了许多区内点，这些点离它较远时，加权占比仍可能低于 `--ring`。因此，常规外环选完后，用核心和已选外环站位共同看到的区内点作为覆盖集合。图像预算还有余量时，继续从占比低于 `--ring` 的区外站位中选取能新增至少 `--ring-min-points` 个未覆盖区内点的站位。每次优先选每张图像能新增最多区内点的站位，并更新覆盖集合，避免重复观测占用名额。

这一轮在核心边界确定后进行，仅使用扣除核心和常规外环后的图像名额。每个补入站位的全部已注册图像一同加入，双鱼眼站位按两张图像计。补覆盖依赖点观测，只有站位近邻图时流程到常规外环为止。

逐区报告核心、扩展和其中补充覆盖的站位数、实际图像数，以及借入前后有观测记录但未被训练图像看到的区内点数和占比。缺少观测记录的区内点单独统计。这个诊断在种子点采样前计算，以便区分视角覆盖不足和种子点选取的影响。

## 5. 汇集训练种子点

1. 以每区核心和扩展站位的图像为入口，沿观测索引收集它们见到的三维点。用原始点索引去重，按源文件顺序写入 `part_points`。同一个点可以被多个区用于初始化。
2. 第一版保留这些图像看到的全部区内点。对看到的区外点，沿用 `outside_seed_fraction` 的确定性采样策略，初始参考值为 `0.2`。这部分点为借入图像中的区外内容提供初始化，合并仍按空间边界裁剪。若要收进全部可见区外点，可将该比例设为 `1`。
3. 只有站位近邻图且仍有种子点时，按空间归属纳入区内点，并记录种子点来源。若有观测的分区缺少区内种子点，报告该区缺少点覆盖。只有位姿时输出空点列表，由训练入口处理初始化。

`point_label` 回答点属于哪块空间。`part_points` 回答哪几个点交给这次训练初始化。把两者分开后，扩展相机借来的点可以参与训练，空间边界仍由第 3 步确定。

## 接入现有分区流程

| 环节 | 接入方式 |
| --- | --- |
| 分区入口 | 在 `ScenePartition` 的公共分区入口加入方法分支。CLI 与 GUI 选择同一方法和场景类型，复用现有数据解析、观测数据、取消和日志。 |
| 区域表达 | 从同一份切面数据生成 `HalfSpaceRegion` 与 `CsgRegion`。一侧用半空间，另一侧用其补集。每个矩形体最多需要六个有效半空间，重复的同向约束只保留最紧的一个。 |
| 保存与读取 | JSON v2 保存场景轴、原点、方向来源和置信度，以及切面树。BIN v3 沿用相机中心和点表。旧版 `LabelField` 分区继续由相应的读取分支载入。 |
| GUI 预览 | 用数据包围盒裁剪无限延伸的外侧边界，仅用于显示。叠加场景轴，显示方向来源和置信度，并分别标记核心和扩展站位。 |
| 训练 ROI | `TrainerCore` 获取该区区域对象，和用户 ROI 求交后按现有流程转到训练坐标并编译。边界上的归属应验证 host 与设备的一致性。现有像素 mask 的射线剔除需要有限的区域包围盒，外围区无界时先沿用种子点投影掩码。 |
| 合并 | `SplatMerge` 先还原到源数据集坐标，再查询该 splat 中心的空间归属，只保留来自所属区的结果。轴对齐区域按位置归属。旧 `LabelField` 方法继续使用带法向的查询。 |

## 验收

- **直路**验证道路轴恢复、每区里程连续、切面垂直于道路轴。用沿道路一侧采集的全景，检查切分前后两侧立面的覆盖，以及扩展站位能否补齐段间接缝。
- **回字形**验证两组正交轴都能恢复。改变闭环的记录起点后，对照四条边和楼角的归属，检查跨记录首尾的一段仍可保持连续。重点查看楼角和闭环接缝是否缺面，以及对侧立面是否被误认为可见。
- **全景站位**验证等距柱状帧和有可靠站位标识的透视面输入，同站视图整组归属和借入，共视点和种子点按原始点索引去重。验证固定区数、图像预算、候选增益排序、切面唯一归属和缺少观测时的诊断。
- 用同一份保存的分区核对重载前后的区域、训练 ROI 与合并保留结果，涵盖跨区观测、训练坐标变换和新旧格式。CUDA 与 Vulkan 都走现有区域程序，检查共享切面附近的判定。
- 两组全景数据都与 `viewgraph`、`graph` 对比共视割边比例、核心连通性、扩展图像数、借入前后的区内未覆盖点比例和合并接缝。用未覆盖点分布定位可能出现缺面的区域。
